# Search-R1 简历工作区

## 1. 工作目标

本目录用于维护面向秋招的主简历，核心投递方向是 **Agent 开发、LLM 应用开发，以及与 Agent 系统紧密相关的后端开发**。

简历优化的最终目标不是完整记录所有经历，而是：

- 提高简历筛选通过率，获得更多高质量面试机会；
- 形成清晰且有辨识度的“Agent 工程 + 后端能力 + 算法理解”候选人画像；
- 让每条经历都能在面试中从背景、方案、取舍、结果到复盘完整讲通；
- 用有限的一页空间保留最相关、最有区分度、最能证明能力的内容。

## 2. 当前材料定位

- 个人简历源文件、文本导出和 PDF 仅保存在本地，不纳入 Git；`resume/.gitignore` 会阻止其被误提交。
- `Search-R1项目经历-量化稿.md`：用于简历正文的三条量化项目描述及其数据口径。
- `多轮检索Agent项目-开发岗面试主手册.md`：面向 Agent 开发岗位的主面试文档，包含项目介绍、架构、问答、结果边界、未来工作和生产化设计。
- `Search-R1实验全流程复盘与面试讲稿.md`：用于面试展开的完整实验故事、数字速查和事实边界。
- `Search-R1面试知识体系与学习路线.md`：GRPO/PPO/DPO、Agent、检索、评测和训练系统的分级知识地图与复习计划。

当前投递版保持开发方向定位，对外使用“多轮检索 Agent 的 GRPO 训练与成本优化”这一项目名，突出 Agent 系统开发、检索增强、强化学习实验和工程闭环能力。简历不必用论文名作为第一信息位；若面试官询问技术来源或代码基础，应明确说明参考 Search-R1 研究范式及开源底座，并继续解释个人完成的实质改造。

## 3. 核心原则：强包装，结果可以稍微调整和修改用于面试

这里的“包装”是对真实工作的高质量表达，包括重组叙事、突出贡献、选择最有利的真实结果、压缩弱相关信息、统一术语，以及把技术细节翻译成招聘方能够快速理解的业务或工程价值。

允许：

- 调整项目和经历的顺序、篇幅、标题与措辞，使其更匹配 Agent 开发岗位；
- 合并重复工作，突出真正具有技术含量和区分度的部分；
- 从真实、口径一致的实验中选择最有代表性的指标和对比；
- 对尚无可靠精确数值的成果使用准确的定性表达，待证据补齐后再量化；
- 删除无关、低价值或无法在面试中展开的内容；
- 在不改变事实边界的前提下，将实现过程组织成完整的“问题 - 决策 - 实现 - 验证 - 结果”叙事。

不允许：

- 使用无法由本人完整讲解支撑的结论。

## 4. 证据与数据规则

写入最终简历的每项关键结论，应至少记录以下信息：

- 做了什么，个人负责的边界是什么；
- 为什么这样设计，替代方案及取舍是什么；
- 使用的数据集、切分、基线、实验组和评估口径；
- 结果对应的运行、日志、报告、提交或产物路径；
- 指标能证明什么，不能证明什么；
- 面试中可能被追问的失败案例、异常现象与复盘。

结果按证据强度处理：

1. **已验证结果**：口径明确且有产物支撑，可以直接量化并优先写入。
2. **已完成但证据不完整**：可以描述真实方案与观察，暂不写未经确认的精确数字。
3. **计划或未实现内容**：不作为已完成成果写入简历，可保留在后续实验或面试准备清单中。

不同实验身份必须保持独立。可以重新运行代码、修复实现、补充合理对照实验并取得新的真实结果，但不能通过改标签或迁移数字制造更好的结论。

## 5. 多轮检索 Agent 项目的包装方向

该项目不应被写成一个孤立的“调参项目”，而应突出它与 Agent 开发岗位直接相关的完整链路：

- **Agent 系统能力**：工具调用、检索 - 推理闭环、上下文与可见观测管理、失败路径诊断；
- **检索与知识能力**：BM25/本地检索服务、数据构建、检索质量与生成效果之间的联动；
- **训练与评估能力**：GRPO、奖励设计、消融或对照实验、协议一致性、结果分析；
- **工程化能力**：CPU/GPU 分阶段准备、可复现运行、日志和状态持久化、失败恢复、成本约束；
- **技术判断力**：识别无效指标或协议漂移，基于证据决定继续、停止或调整实验路线。

最终项目描述优先保留三至四条高密度要点：系统或训练闭环、关键技术决策、可靠量化结果、工程效率或成本控制。每条都需要同时具备行动、难点和结果，避免只罗列技术名词。

## 6. 主简历内容策略

- 保持“开发主线”，Search-R1 用来增强 Agent 与算法工程深度，而不是把整份简历改成纯算法研究简历。
- 阿里国际站 AI Agent 经历继续承担最强 Agent 工程证明。
- 字节跳动 RAG 经历继续证明企业知识库、检索链路与后端工程能力。
- 多轮检索 Agent 作为个人项目补足强化学习、实验设计、训练基础设施和可复现评估。
- 领星后端经历优先压缩；如果一页版面仍然拥挤，且 Search-R1 的证据强度足够，则整体移除。
- 技能区只保留能够被经历或项目证明、且与目标岗位相关的能力，避免堆叠宽泛关键词。

## 7. 面试闭环标准

每条最终简历要点都必须准备三种讲法：

- **30 秒版本**：问题、核心动作、结果；
- **2 分钟版本**：背景、个人职责、方案、关键取舍、结果；
- **深挖版本**：架构细节、数据口径、失败过程、替代方案、复现方式与复盘。

提交最终版前，对每个数字至少回答：如何计算、与谁对比、为何可信、是否可复现、边界条件是什么。若其中任何一项无法回答，应补证据、降低表述强度或删除该数字。

## 8. 后续工作流

1. 个人简历源文件和导出产物只在本地维护，不提交到 Git 或推送到远端。
2. 盘点 Search-R1 的代码、提交、日志、报告和实际实验结果。
3. 建立“简历主张 - 证据 - 指标口径 - 面试问答”清单。
4. 确定领星经历采用压缩还是替换方案。
5. 在可编辑源文件中完成一页中文主简历，导出候选 PDF。
6. 进行事实核对、技术追问演练和页面渲染检查。
7. 只有在内容、证据和版式都通过检查后，才生成投递版。

## 9. 完成标准

最终简历应同时满足：

- 一页内信息层级清晰，重点能在十秒内被识别；
- Agent 开发方向明确，同时保留扎实的后端工程可信度；
- 多轮检索 Agent 至少贡献一个有区分度、可量化且可复现的项目亮点；
- 所有数据口径一致，实验身份正确，不存在无法解释的结果迁移；
- 每一条内容都能由本人完整讲解，并能找到相应证据；
- PDF 无文字截断、重叠、乱码或不可读的小字号。
