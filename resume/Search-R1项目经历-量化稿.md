# 多轮检索 Agent 项目经历量化稿

## 推荐项目标题

**多轮检索 Agent 的 GRPO 训练与成本优化**

技术栈可写为：`Qwen3.5-2B / PyTorch / verl / Ray / FSDP / vLLM / BM25 / GRPO`

## 项目总览

**从“学会检索”到“低成本检索”：**围绕“是否检索、如何检索、何时停止”三类决策，分阶段提升多轮检索 Agent 的回答质量与工具调用效率，并形成覆盖策略训练、成本控制与效果验证的完整闭环。

## 可直接替换的三条文本

- **Agent 架构：**面向开放域多跳问答，设计并实现 Qwen3.5-2B 多轮检索 Agent，以原生 Tool Calling 串联“推理—检索—回填—作答”闭环，接入 BM25 Top-3 检索服务，并实现 4 次检索预算、终局提醒作答与环境 Token 损失掩码。
- **强化学习训练：**在 2×5090 级 GPU 上以答案奖励完成全参数 GRPO 训练，采样 2,400 条轨迹，使 512 题 strict EM 21.29%→39.45%、检索量下降 21.8%；再基于同一权重分叉对照/成本优化分支，针对线性成本引发的 98.44% 不搜索坍缩，引入仅作用于正确轨迹的 Correctness-Gated Reward，在 EM 基本持平下进一步减少 8.18% 检索。
- **评测验证：**搭建统一评测与轨迹审计流水线，完成 4 个模型在 NQ/HotpotQA 混合验证集、NQ 单跳测试集和 HotpotQA/2Wiki 多跳测试集上的 2,048 条轨迹验证；GRPO 主模型相较基线的 strict EM 均提升 15.23–25.00pp。

## 数据口径备忘（不放入简历正文）

- `NQ/HotpotQA 混合验证集（val-128）`：NQ 64 题、HotpotQA 64 题；两部分均为未进入训练的 held-out 题目。
- `NQ 单跳测试集（NQ-test-128）`：NQ 128 题。
- `HotpotQA/2Wiki 多跳测试集（multihop-256）`：HotpotQA 128 题、2WikiMultihopQA 128 题；2Wiki 只用于独立测试，未进入训练或混合验证集。
- `512 题`：上述三组数据合计 128 + 128 + 256 题。
- `12 组 2,048 条评测`：A、R、B、C 四个模型分别运行三组评测集，共 12 个模型-评测集组合；按模型-问题轨迹计共 2,048 条。
- A→R：strict EM 为 `109/512→202/512`，即 `21.29%→39.45%`；总搜索 `1690→1321`，下降 `369/1690=21.83%`。
- B→C：strict EM 为 `186/512→190/512`，即 `36.33%→37.11%`；总搜索 `1320→1212`，下降 `108/1320=8.18%`；4-search 饱和轨迹为 `196/512→155/512`，即 `38.28%→30.27%`。
- 三组评测集的 A→R strict EM 配对 bootstrap 95% CI 均不跨 0；B→C 的准确率点估计基本持平，主要成果是搜索效率改善。

- 可以说“我实现并改造了这个项目”“我负责了核心实验闭环”；不要说“整个框架从零手写”“我提出了 GRPO”或“这是完全原创算法”。
