# Qwen3.5 Native A/R/B/C 最终结果分析

> 分析日期：2026-08-02
>
> 范围：只分析最终 A/R/B/C 结果，不复述训练崩溃、恢复过程、数据配比调整或项目开发历史
>
> 主指标：strict exact match（EM）；成本效用统一为 `U = EM - 0.025 × executed_searches`

## 1. 最终结论

这组结果没有一个在所有目标上都绝对最优的模型，但模型定位已经很清楚：

1. **A→R 是本轮最明确、最可靠的能力提升。** R 在 val、NQ-test、multihop 三个端点上分别比 A 提高 `+25.00`、`+17.19`、`+15.23` 个百分点，三条逐题配对 bootstrap 置信区间都不跨 0；512 行描述性汇总中，R 比 A 多答对 93 题，同时少执行 369 次搜索。
2. **R 是当前更稳妥的综合能力端点。** R 在 NQ-test 和 multihop 上均为四模型第一；尤其 multihop 为 `95/256=37.11%`，明显高于 B 的 `30.08%` 和 C 的 `29.69%`。按 512 行原始样本加权，R 的 EM 和当前定义的 utility 点估计也最高。
3. **C 确实比 B 更像一个成功的成本分支。** C 相比 B 多答对 4 题、少搜索 108 次、平均 token 更少、utility 点估计更高。因此“C 略好于 B”的直觉是合理的；但三个端点的 C−B EM 置信区间都跨 0，不能说 C 已被证明比 B 更准确。
4. **C 不是四模型中的无条件最佳模型。** C 只在 val 上排名第一；在 NQ-test 略低于 R 1 题，在 multihop 低于 R 19 题。C 的价值是降低检索成本，而不是已经确认提高通用能力。
5. **B/C 的后续 20 步没有稳定超过 R。** B 的 512 行总搜索量几乎与 R 相同（`1320` 对 `1321`），却少答对 16 题；C 虽比 R 少搜索 109 次，但也少答对 12 题，主要代价集中在 multihop。
6. **协议质量仍然是结果的主要限制。** clipped trajectory 比例从 A 的 `17.97%` 上升到 R 的 `38.09%`，再到 B/C 的约 `71%`。因此 token 变短不能全部解释为更简洁，其中一部分受到生成截断影响。

如果现在必须选一个默认 checkpoint：

- 以正确率、multihop 和综合泛化为先：选 **R**；
- 以检索成本为先，并能接受 multihop 风险：把 **C** 作为低成本候选；
- 在 B/C 两个分支中：保留 **C**，但结论应写成“效率更好、准确率未确认提高”；
- **B** 没有显示出相对 R 或 C 的明确部署优势；
- **A** 只作为训练前基线。

## 2. 比较对象与可比性

| 名称 | 模型身份 | 作用 |
|---|---|---|
| A | sealed post-trained Qwen3.5-2B parent，digest `bc67be20…64e78` | 未经本轮 RL 的 parent 基线；不是官方 Base 变体 |
| R | direct-RL R60，digest `583771b1…c231` | 60 步直接 outcome-RL 端点 |
| B | R60 后续 B20 control，digest `8df3d6ab…ad6d2` | 再训练 20 步，`cost_lambda=0` |
| C | R60 后续 C20，digest `106b6289…fa4b2e` | 再训练 20 步，`cost_lambda=0.10`、`correct_only` gate |

三套评测均满足以下条件：

- val 128 题、NQ-test 128 题、multihop 256 题；
- A/R 与 B/C 使用的 Parquet SHA、sample-ID SHA 完全一致；
- 逐题 CSV 的 ID 集合、行序、问题文本和 gold answers 均完全一致，无重复 ID；
- greedy、`do_sample=false`、group size 1、每题 1 条 rollout、seed 42；
- 按 `typed_sample_id` 配对，样本集合和顺序均为 exact match；
- 四个 checkpoint 在三个端点中的 digest 均保持不变。

因此四模型可以做同题、同协议的描述性横向比较。正式封存的配对统计是 R−A 和 C−B；本报告新增的 R−B、R−C 横向检验明确标为 post-hoc。

## 3. 四模型主结果

### 3.1 Strict EM

| 评测端点 | A | R | B | C | 端点第一 |
|---|---:|---:|---:|---:|---|
| val-128 | 43/128，33.59% | 75/128，58.59% | 79/128，61.72% | **83/128，64.84%** | C |
| NQ-test-128 | 10/128，7.81% | **32/128，25.00%** | 30/128，23.44% | 31/128，24.22% | R |
| multihop-256 | 56/256，21.88% | **95/256，37.11%** | 77/256，30.08% | 76/256，29.69% | R |
| 512 行描述性汇总 | 109/512，21.29% | **202/512，39.45%** | 186/512，36.33% | 190/512，37.11% | R |

512 行汇总将 256 题的 multihop 权重设为两个 128 题端点的两倍，所以它不是一个自然存在的统一 benchmark。如果改为三个端点等权的 macro average，A/R/B/C 分别为 `21.09% / 40.23% / 38.41% / 39.58%`：R 仍为第一，但只比 C 高 `0.65pp`。这说明“谁综合最好”会受到部署任务权重影响。

### 3.2 搜索量

| 评测端点 | A | R | B | C | 最少搜索 |
|---|---:|---:|---:|---:|---|
| val-128 | 3.234 / 414 | 1.992 / 255 | 1.930 / 247 | **1.680 / 215** | C |
| NQ-test-128 | 2.727 / 349 | 2.523 / 323 | 2.234 / 286 | **2.086 / 267** | C |
| multihop-256 | 3.621 / 927 | 2.902 / 743 | 3.074 / 787 | **2.852 / 730** | C |
| 512 行描述性汇总 | 3.301 / 1690 | 2.580 / 1321 | 2.578 / 1320 | **2.367 / 1212** | C |

表中为“每题平均搜索 / 总搜索”。C 在三个端点的点估计上都最省搜索，但 NQ-test 的 C−B 搜索差异区间跨 0；不能把每个端点都写成已确认下降。

### 3.3 512 行综合质量画像

| 模型 | EM | 平均搜索 | Utility | 平均 tokens | 含 invalid 轨迹 | clipped 轨迹 | 无 clip 且无 invalid |
|---|---:|---:|---:|---:|---:|---:|---:|
| A | 21.29% | 3.301 | 0.1304 | 2255.2 | 275/512，53.71% | 92/512，17.97% | 237/512，46.29% |
| R | **39.45%** | 2.580 | **0.3300** | 2009.0 | 184/512，35.94% | 195/512，38.09% | **276/512，53.91%** |
| B | 36.33% | 2.578 | 0.2988 | 1754.5 | **177/512，34.57%** | 363/512，70.90% | 87/512，16.99% |
| C | 37.11% | **2.367** | 0.3119 | **1677.1** | 194/512，37.89% | 367/512，71.68% | 59/512，11.52% |

这里的 utility 只惩罚检索次数，不惩罚 token、invalid 或 clipping，因此不能把它解释成整体可靠性分数。

按 512 行原始样本加权时，R 的 utility 高于 C：`0.3300` 对 `0.3119`。如果让三个端点等权，R 与 C 几乎完全相同：`0.34053` 对 `0.34069`。所以 R/C 的最终选择不应依赖一个任意汇总权重，而应依赖目标流量中 multihop 的实际占比。

## 4. A→R：本轮最可靠的主结果

下表全部来自封存的 10,000 次题目级 paired percentile bootstrap，seed 42。

| 端点 | R−A EM（95% CI） | 错→对 / 对→错 | 搜索差（95% CI） | token 差（95% CI） | clipping 差（95% CI） |
|---|---:|---:|---:|---:|---:|
| val | **+25.00pp [15.63, 34.38]** | 39 / 7 | **−1.242 [−1.492,−0.977]** | **−630 [−796,−451]** | **+32.03pp [22.66,41.41]** |
| NQ-test | **+17.19pp [10.16,25.00]** | 25 / 3 | −0.203 [−0.492,+0.102] | −35 [−223,+156] | **+25.00pp [14.84,35.16]** |
| multihop | **+15.23pp [9.77,21.09]** | 50 / 11 | **−0.719 [−0.875,−0.566]** | **−160 [−252,−69]** | **+11.72pp [5.08,18.36]** |

这组结果支持三个明确判断：

1. **R 的正确率提升不是 val 偶然波动。** 三个端点的 EM 区间下界都大于 0，且错→对远多于对→错。
2. **R 不是靠更多检索换正确率。** val 与 multihop 同时出现显著的 EM 上升、搜索下降、action 下降和 token 下降。A→R 新增正确题中，搜索次数下降的比例分别为 val `30/39`、NQ-test `16/25`、multihop `34/50`。
3. **NQ-test 的效率结论较弱。** 它的 EM 提升明确，但搜索、token 和平均 invalid action 的 CI 都跨 0，因此这里只能确认“更准”，不能确认“显著更省”。

512 行描述性汇总中：

- 正确数 `109→202`，增加 93；
- 总搜索 `1690→1321`，减少 369；
- 平均 token `2255.2→2009.0`；
- 含 invalid 的轨迹 `53.71%→35.94%`；
- clipped trajectory `17.97%→38.09%`。

最后一项是必须保留的负面结果：R 的能力和部分搜索效率明确提高，但 clipping 在三个端点上也都显著增加。因而最准确的表述是“能力提升明确、val/multihop 效率改善，同时生成截断恶化”，而不是“R 全面改善”。

## 5. B→C：效率提升比准确率提升更可信

本节 EM、搜索及其他行为指标的区间来自封存 summary。Utility 差值区间是本报告基于同一 `paired_results.csv`，沿用 10,000 次、seed 42 的题目级 paired percentile bootstrap 做的 post-hoc 重算，不是原 summary 预置字段。

| 端点 | C−B EM（95% CI） | 错→对 / 对→错 | 搜索差（95% CI） | Utility 差（95% CI） |
|---|---:|---:|---:|---:|
| val | +3.13pp [−2.34,+8.59] | 9 / 5 | **−0.250 [−0.406,−0.102]** | +0.0375 [−0.0190,+0.0969] |
| NQ-test | +0.78pp [−6.25,+7.81] | 11 / 10 | −0.148 [−0.375,+0.086] | +0.0115 [−0.0590,+0.0824] |
| multihop | −0.39pp [−5.47,+4.30] | 20 / 21 | **−0.223 [−0.340,−0.105]** | +0.0017 [−0.0494,+0.0505] |

对 C 最合适的解释是：

- EM 点估计为 val 多 4 题、NQ-test 多 1 题、multihop 少 1 题；三个区间全部跨 0，所以没有确认性证据证明 C 比 B 更准确。
- 总搜索从 `1320` 降到 `1212`，少 108 次，即 `−8.18%`；val 和 multihop 的逐题搜索下降有 bootstrap 支持。
- 总 token 从 `898,309` 降到 `858,661`，平均少 77.4 token；但 B/C 都存在很高 clipping，不能把它全部解释为主动简洁化。
- 108 次搜索节省中，81 次来自 B、C 都答错的同题轨迹，占 `75.0%`。这说明 C 的主要收益是减少无效尝试，而不是稳定增加解题数。
- 4-search 饱和率从 B 的 `38.28%` 降到 C 的 `30.27%`；两者都只有 `1/512` 零搜索轨迹，所以 C 没有退化成“为省成本而不搜索”。
- C 的 invalid trajectory 比 B 更高（`37.89%` 对 `34.57%`），clipping 也基本相同。本次 C 分支观测到更浅的搜索路径，但不能把差异单独归因于成本奖励；无论原因如何，它没有修复协议稳定性。

所以，用户此前的判断可以精确改写为：

> C 相比 B 的综合点估计确实略好，而且检索成本更低；但它的准确率优势很小且未得到统计确认。C 的可信成果是效率，不是能力升级。

## 6. R 与 B/C：为什么 R 仍是综合能力首选

下面是从两份已封存逐题表按相同 sample ID 追加得到的 post-hoc exact McNemar 比较。它不是原 summary 预置的正式对比，p 值也未在本表内做多重校正。

| 端点 | R / B / C 正确数 | B−R EM；p | C−R EM；p | C−R 平均搜索 | C−R Utility |
|---|---:|---:|---:|---:|---:|
| val | 75 / 79 / 83 | +3.13pp；0.503 | +6.25pp；0.096 | −0.313 | +0.0703 |
| NQ-test | 32 / 30 / 31 | −1.56pp；0.832 | −0.78pp；1.000 | −0.438 | +0.0031 |
| multihop | 95 / 77 / 76 | −7.03pp；0.00792 | **−7.42pp；0.00432** | −0.051 | **−0.0729** |

这里最重要的是端点异质性：

- val 偏向 C：比 R 多答对 8 题，同时平均少 0.313 次搜索；
- NQ-test 基本打平：C 少答对 1 题，但平均少 0.438 次搜索；
- multihop 明确偏向 R：C 只平均少 0.051 次搜索，却少答对 19 题，utility 也明显更低。

如果把四模型三个端点共 18 个 exact McNemar 两两检验组成一个事后敏感性 family，并机械应用 Holm 校正，multihop 的 R>C 仍约为 `p=0.0476`，R>B 则约为 `p=0.0633`。这支持“R 对 C 的 multihop 优势值得重视”，但仍不能替代多训练 seed 的确认性复验。

从整体点估计看，B 的定位最弱：它与 R 的总搜索几乎完全一样，却少答对 16 题；C 至少用更少搜索换来了接近 R 的平均能力。后续 20 步训练在这一次固定运行中表现为 val 上升、multihop 下降，更像分布特化而不是无条件继续提升。

## 8. 搜索行为与轨迹质量

### 8.1 搜索分布

| 模型 | 0-search | 4-search 饱和 | 正确题平均搜索 | 错误题平均搜索 |
|---|---:|---:|---:|---:|
| A | 23/512，4.49% | 350/512，68.36% | 2.982 | 3.387 |
| R | 13/512，2.54% | 179/512，34.96% | 2.059 | 2.919 |
| B | 1/512，0.20% | 196/512，38.28% | 1.925 | 2.951 |
| C | 1/512，0.20% | **155/512，30.27%** | **1.779** | **2.714** |

A 大量撞满 4-search 预算；R 将饱和率接近减半，同时显著提高正确率。C 进一步压低 4-search 比例，而且没有引发零搜索坍缩。这个行为证据比 C 的微小 EM 点差更有说服力。

### 8.2 Invalid 与 clipping 不能混为一谈

- A→R 后，含 invalid 的轨迹从 275 降到 184，但 clipped trajectory 从 92 增到 195；能力提升伴随一种新的截断风险。
- B/C 的 invalid 轨迹率约为 35%–38%，与 R 同量级；但 clipping 升到约 71%，使“无 clip 且无 invalid”的比例从 R 的 `53.91%` 降到 B 的 `16.99%`、C 的 `11.52%`。
- clipping 并不等同于答案一定错误，但会让 token 长度、搜索停止和终局格式指标产生删失混杂。B/C 平均 token 更短，只能说“观测到的输出更短”，不能无条件说“推理更简洁”。
- utility 不包含 invalid、clipping 或 token 惩罚，因此 utility 提高不能抵消轨迹质量问题。

## 9. 最终模型定位

| 使用目标 | 当前建议 | 理由 |
|---|---|---|
| 最高原始能力、multihop、默认研究基线 | **R** | 两个泛化端点第一；512 行 EM 第一；无 clip 且无 invalid 比例最高 |
| 低检索成本、val/NQ-like 流量 | **C 候选** | 三端点搜索点估计最低；相对 B 明确减少检索；val 第一 |
| B/C 分支二选一 | **C** | 相比 B 多对 4 题、少搜 108 次，但准确率优势未确认 |
| 继续使用 B | 不建议作为默认 | 与 R 总搜索几乎相同但少对 16 题，也不如 C 省成本 |
| 未训练基线 | A | 只用于量化 direct RL 的净提升 |

最终不是“R 胜出、C 失败”，而是两个不同的 Pareto 端点：

- R 更偏能力和 multihop 稳健性；
- C 更偏检索成本和短搜索路径；
- C 训练使用 `cost_lambda=0.10`；此处报告 utility 仍按 `EM - 0.025 × searches` 计算。在这个统一评估定义下，两者若按三个端点等权，utility 几乎打平；一旦真实业务更重视 multihop，R 会明显占优。

## 10. 统计边界

1. 所有正式 CI 都是固定 checkpoint 下的题目级 paired bootstrap，只覆盖题目抽样不确定性，不覆盖训练 seed、checkpoint 选择或训练方差。
2. 每种模型只有一个训练端点；greedy、每题单 rollout，无法估计解码方差。
3. R−A 与 C−B 是封存 summary 的预置比较；R−B、R−C、来源切片和合并结果都是 post-hoc。
4. 三个端点的点估计与 CI 未统一做预注册的多重比较控制；不能从单个较小 p 值扩大到算法普遍因果有效。
5. strict EM 会对 alias、日期格式和冗长答案敏感，但四模型使用相同 scorer，因此逐题差值仍可公平比较。
6. 512 行合并结果给 multihop 两倍权重；macro average 又会给三个端点同权。两者都只是人为汇总，最终部署结论应按真实流量加权。
7. B/C 是单 seed 的探索性 recovery 结果，且 B/C 训练 checkout 不是 bit-identical；不能把本次分支差异写成跨运行稳定的算法因果结论。
8. 高 clipping 会影响 token、搜索停止和轨迹完整性，是当前横向排名之外最重要的质量风险。
