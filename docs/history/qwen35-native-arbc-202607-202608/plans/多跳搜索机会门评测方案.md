# 多跳搜索机会门评测方案

## 目的与边界

本实验先回答一个问题：现有 B/control 模型在真正的多跳题上，是否会进行足够多且可压缩的搜索，从而值得再训练成本感知分支。代码位于独立分支 `experiment/hotpot-search-gate`；原成本实验分支、R/B/C checkpoint 和历史结果均不修改。

本轮只评测 B，不训练，不修改奖励函数，不评 R/C，也不重新运行 NQ。若门禁为 NO-GO，保留结果后回到原分支即可。

## 固定数据

数据固定为 `RUC-NLPIR/FlashRAG_datasets@bcafb8d`。CPU 阶段只下载两个 dev JSONL，并把其仓库内路径、字节数和 SHA-256 写入 manifest 与 handoff：

- HotpotQA dev：固定 seed 抽取 128 题；包含 comparison/bridge 与 easy/medium/hard 等 metadata。
- 2WikiMultiHopQA dev：固定 seed 抽取 128 题；主要包含 compositional/comparison 等类型。

两组题合并成一次 256 题评测，以避免重复加载模型。每次 verify 都从固定原始 JSONL 按 seed 重算选择并逐题核对 catalog，防止只重封 manifest 就替换样本。模型 prompt 只包含问题，不包含 benchmark context 或 supporting facts；检索仍使用与既有实验相同的 Wiki-18 BM25。`hop_proxy` 等于去重 supporting title 数，只用于分层，不能解释为“理论所需搜索次数”。

## 三阶段执行

1. **Git**：把本分支固定到一个完整 commit；保留历史 checkpoint，不覆盖原分支。
2. **CPU 无卡**：运行 `AUTODL_SEARCH_GATE_INCREMENTAL=1 bash scripts/autodl/02_cpu_prepare.sh`。只新增两个 dev split、生成 Parquet/catalog/manifest，并复用已有环境、模型、索引和语料重封 handoff。
3. **GPU 两卡**：运行 `GPU_COUNT=2 AUTODL_PRICE_PER_HOUR=<整机价> bash scripts/autodl/06_gpu_search_opportunity_gate.sh`。仅加载 B/control20，一次完成 256 题并输出完整轨迹。GPU 分项硬上限 10 元（5.76 元/小时时约 104 分钟），仅用于防止失控运行。

GPU 启动后，将入口打印的 exact attempt 交给 `04_watch_and_shutdown.sh`。GO 与 NO-GO 都属于正常科学终态；证据写完且校验通过后均可触发安全关机。

## 预注册门禁

数据完整性、trace/catalog 256 题一一对应、每数据集 128 题是硬条件。默认继续训练需同时满足：

- B 总答对数不少于 20；
- 答对题中 `search >= 2` 不少于 8，且占答对题至少 20%；
- 全部题中 `search >= 3` 不少于 10；
- strong/medium 冗余候选不少于 5，且占三搜题至少 30%；
- response clipped 与 invalid-action 样本比例分别不高于 5%。

“冗余候选”仅依据重复 query、无新增文档、低文档新颖度或最终答案在此前 observation 中已经出现。它不能证明删掉该次搜索后答案不变；真正反事实验证留到门禁通过之后。

## 证据与后续决策

输出包含 `summary.md/json`、`go_no_go.json`、逐题完整 `per_question.jsonl`、答对/答错清单、两搜以上清单、冗余候选及各数据集/题型/难度/hop proxy 分层表。所有输入、trace、lineage 和报告均进入 `evidence.sha256`。

- **GO**：只说明现有 B 在多跳 dev 上表现出可观察的多搜索机会。后续必须从未使用的 HotpotQA/2Wiki train split 固定一个小训练集，并从同一 parent 分别训练原奖励 `B-multihop` 与成本奖励 `C-multihop`，再在本次固定 dev-256 上配对比较；不能把仅在 NQ 上训练的 B 与额外见过多跳训练数据的 C 直接比较。
- **NO-GO**：不继续烧 GPU；结论仅限于当前 B 在这组多跳 dev 上没有表现出足够的正确多搜索轨迹，而不是继续调奖励直到得到正结果。
