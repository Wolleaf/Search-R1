# 训练配置差异审计报告

## 1. 结论

审计基线为论文 `2503.09516v5.pdf`、原仓库 `main@598e61b`、官方 GRPO recipe `scripts/nq_hotpotqa/v0.2/train_grpo.sh`，以及当前实现 `feature/reproduct-cost-aware@106a9c3`。

结论如下：

1. **R（Reproduced）和 B（Control）的奖励没有被擅自修改，仍是原始 normalized Exact Match（EM）。** 只有用户要求的 C（Cost-aware）加入检索成本。
2. `106a9c3` 将搜索上限从 2 恢复为 4 时，没有夹带修改学习率、warmup、group size、采样、KL、优化器、数据或奖励 scorer；相关联的变化只有 prompt 上限和成本归一化分母。
3. 当前仍有多项会改变结果的缩小配置，其中模型、算法、group size、数据、检索器、batch、steps 和 token 长度来自已确认的小规模方案；项目应表述为 **Search-R1-small 的 NQ-only 方法复现与成本感知消融**，不能声称复刻论文数值。
4. 两项偏离没有显存或 Qwen3.5 兼容理由：`warmup=0.10`（论文及官方 recipe 为 `0.285`）和 `top_p=0.95`（论文为 `1.0`）。正式重训前应优先决定是否恢复；本报告不修改代码。

## 2. 奖励函数专项审计

当前三路训练奖励为：

```text
R / Reproduced: r = EM
B / Control:    r = EM
C / Cost-aware: r = EM - 0.10 * executed_search_count / 4
```

- R 和 B 的 `cost_lambda` 均为 0，C 才为 0.10，见 `scripts/autodl/train_small_grpo.sh:54`、`:80`、`:82`。
- `verl/trainer/main_ppo.py:104` 仍调用原 `qa_em.compute_score_em`，`:107` 才从终局 EM 中减成本。lambda 为 0 时，R/B 的 reward 数值与原仓库逐项相同。
- `verl/utils/reward_score/qa_em.py` 与 `origin/main` 的 Git blob 均为 `6e028203...`，没有修改。答对为 1，答错或答案格式不合法为 0；不存在新增的正向 format reward。
- `verl/trainer/ppo/core_algos.py` 与 `origin/main` 的 Git blob 均为 `d3f4aff3...`，GRPO advantage、clip loss 和 KL 公式没有修改。
- `verl/trainer/config/ppo_trainer.yaml:132` 禁用 reward model，`:148-150` 的 structure、final-format、retrieval shaping 均为 0。无效 action 只沿用原有纠错 observation，没有数值惩罚。
- 真实检索计数仅在请求实际发给 retriever 时增加，见 `search_r1/llm_agent/generation.py:391`；最后一次 `do_search=False` 的强制回答不计费。

当 `T_max=4` 时，C 每次检索扣 `0.025`，四次最多扣 `0.10`。这是“固定最大总成本”的设计；`lambda=0.10` 和按上限归一化是本项目的实验超参，不来自原论文，也没有经过 sweep。

A/R/B/C 最终评测统一用 lambda 0.10 计算 post-hoc utility，但同时分别记录 EM、平均搜索次数和 no-search ratio，见 `scripts/autodl/train_small_grpo.sh:96` 和 `scripts/autodl/results.py:15`。这不会反向改变 A/R/B 的训练。

## 3. 从 2 改为 4 的提交审计

提交 `106a9c3 set search budget to four` 只涉及规划文档、AutoDL 配置/汇总脚本及相应测试，没有修改 `search_r1/` 或 `verl/` 核心训练代码。科学配置变化限定为：

- 固定 `MAX_TURNS=4` 和 retriever top-k=3：`scripts/autodl/train_small_grpo.sh:17-20`。
- 将 `max_prompt_length` 从旧值 2048 改为派生值 `1024 + 4 * (256 + 384) = 3584`，避免第四轮历史在最终回答前被截断：同文件 `:31`、`:140`。
- 训练和评测统一传入 `max_turns=4`：同文件 `:193`。
- 最终 utility 的分母由 2 改为 4：`scripts/autodl/results.py:21-22`、`:127-128`。
- CPU gate 全量比较 B/C resolved config，除 `cost_lambda` 和实验名外有任何差异都会失败：`scripts/autodl/02_cpu_prepare.sh:325-337`。

因此，本次“2 -> 4”没有顺带改变奖励 lambda、LR、warmup、group size、sampling、KL、optimizer、数据或训练步数。

## 5. 训练逻辑与评测差异

以下代码变化会影响精确数值轨迹，但不是奖励篡改：

- 新增 seed=42 并给不同 rank 派生 seed，使 B/C 数据顺序和随机源可复现；这属于正确性增强。
- generation 现在透传 `meta_info`，从而让验证阶段的 `do_sample=false` 真正进入 agent loop；这是修复确定性评测。
- 训练循环修复了 total steps 的 off-by-one，声明 60/20 就实际完成 60/20 次更新；与原仓库 bug 无法逐 bit 一致，但符合配置语义。
- actor/critic 将 FlashAttention import 移入 `use_remove_padding` 分支，并支持 SDPA；这是 Qwen3.5/5090 兼容改动，不改变 loss 公式。
- 日志精度从 3 位提高到 6 位，并新增 EM、search count、utility 等分解指标；只影响记录和审计。

B/C 都从同一个 R60 **模型权重**启动，但重新创建 AdamW、scheduler、DataLoader 和 RNG 状态。因此它们是公平的 stage-2 分叉，不是 R 的 optimizer 精确续训，也不能把 B20 表述成连续的 R step 61-80。两支仍是公平对照，因为 CPU gate 保证除 lambda 和实验名外 resolved config 完全相同。

当前 agent loop 在 4 次允许搜索的生成后，还会为未结束样本执行一次 `do_search=False` 的最终回答生成，见 `search_r1/llm_agent/generation.py:237-303`。这是原仓库实现语义的延续，可表述为“最多 4 次实际检索，必要时再给一次禁止检索的收尾回答”。

## 6. 风险边界与最小建议

### 正式训练前建议恢复

1. 将 `actor_rollout_ref.actor.optim.lr_warmup_steps_ratio` 从 `0.10` 改回论文和官方 recipe 的 `0.285`。
2. 若以论文而不是发布代码默认值为最高依据，将 rollout `top_p` 从 `0.95` 显式改为 `1.0`。

### 不建议再动

- 不修改 EM scorer、GRPO advantage、KL、clip、LR、loss masking、top-k=3 或 `T_max=4`。
- 不再调整 group size 8；它是用户明确选择，B/C 使用同值即可保证主对照公平。
- 不在本轮引入 PPO、dense retriever、HotpotQA、多 seed 或超参 sweep；这些会越过当前预算和最小实现边界。

### 结果陈述边界

- 主结论只能来自同一 R60 分叉的 **B vs C**；A vs R 是方法 sanity check。
- 单 seed、test-128、NQ-only 和 BM25 条件下，只报告观察到的 EM/检索成本权衡，不宣称统计显著或复现论文榜单。
- 当前结果工具保存聚合指标和训练日志，但没有保存 test-128 的逐样本预测、EM 与搜索次数；这不阻塞训练，但会限制后续 paired error analysis 和 bootstrap 置信区间。
