你这个质疑抓到了一个真实的设计取舍。先给结论：

- 原论文不是 2 次，而是最大 action budget `B=4`，每次搜索返回 Top-3。
- 当前 `max_turns=2` 是我们为了 NQ-only、两卡低成本复现做的缩小，不是论文原始配置。
- 搜索上限和搜索惩罚并不重复：上限控制“最多能花多少”，惩罚控制“在允许范围内是否值得搜索”。
- 但从论文一致性、Agent 架构展示和面试可解释性来看，`B=4` 确实比 `B=2` 更合适；`B=5` 没有论文依据，不推荐。

## 论文原版配置

论文附录 B 明确写了：

> The maximum action budget B is set to 4, and we retrieve the top 3 passages by default.

见 [2503.09516v5.pdf](../reference/2503.09516v5.pdf) 第 16 页。

论文的训练数据也不只是 NQ，而是：

```text
NQ + HotpotQA
```

其中 HotpotQA 本身就是多跳问答。论文最终还评测了 2WikiMultiHopQA、MuSiQue、Bamboogle 等多跳数据集。因此论文使用 `B=4` 是有实际任务需求的。

仓库原来的多机配置同样是 `max_turns=4`，见 [multinode.md](../reference/multinode.md)。

当前缩小版则是：

```text
NQ train-512 / val-64 / test-128
max_turns=2
topk=3
```

见 [autodl_search_r1_reproduction_plan.md](qwen35-native-arbc-202607-202608/plans/autodl_search_r1_reproduction_plan.md)。

所以准确表述应该是：当前是 “Search-R1 的 NQ 单跳缩小复现”，不是完整论文配置复现。

## 有上限后，成本惩罚还有意义吗

有意义。两者解决的问题不同：

- `max_turns` 是硬约束：防止 Agent 无限搜索。
- 搜索成本是软目标：在 0、1、2 次搜索都合法时，鼓励模型选择更少但足够的搜索。

例如原始奖励只有 EM 时：

```text
不搜索答对：1
搜索两次答对：1
```

模型没有动力区分二者，甚至可能形成“遇到任何问题都先搜索”的习惯。

成本奖励后：

```text
不搜索答对：1.00
搜索一次答对：0.95
搜索两次答对：0.90
```

它会学习“需要时搜索，不需要时直接回答”。所以成本项仍有意义，只是 `B=2` 让可优化的搜索范围比较窄，B/C 差异可能不够明显。

## 必须搜索两次的问题怎么办

当前实现其实允许：

```text
搜索 1
→ 搜索 2
→ 最终回答
```

因为代码先执行两轮可搜索交互，然后对仍未结束的轨迹再进行一次不可搜索的最终生成，见 [generation.py](../../search_r1/llm_agent/generation.py)。

所以“两次搜索后回答”是可行的。

而且必要搜索不会天然被成本奖励压掉：

```text
不搜索但答错：0
搜索两次并答对：0.90
```

`0.90` 仍然远高于 `0`，GRPO 理论上会偏好成功的两次搜索轨迹。

真正的风险是探索不足：如果一个 2B 模型在同一组 8 条轨迹里，始终采样不到“搜索两次后答对”的成功轨迹，那么它只看到：

```text
不搜索答错：0
搜索后仍答错：-0.05 或 -0.10
```

这时就可能错误地学成“不搜索”。我们先做 R60 原奖励训练、再加成本分支，正是为了先让模型学会搜索，再压缩不必要搜索，缓解这个问题。

## 2、3、4、5 怎么选

当前公式是：

```text
Reward = EM - 0.10 × search_count / B
```

因此不同上限下的单次成本是：

| 最大预算 B | 每次搜索扣分 | 最大累计扣分 | 评价 |
|---:|---:|---:|---|
| 2 | 0.050 | 0.10 | 便宜，但搜索空间偏窄 |
| 3 | 0.033 | 0.10 | 折中，但没有论文依据 |
| 4 | 0.025 | 0.10 | 论文原配置，最容易解释 |
| 5 | 0.020 | 0.10 | 成本信号更弱、运行更慢，无明显必要 |

我会推荐 `B=4`，而不是 3 或 5。理由是：

- 与论文一致；
- 能容纳多跳和一次失败后的查询修正；
- 面试时不需要解释“为什么随意选 3 或 5”；
- 总最大惩罚仍保持 `0.10`，两次必要搜索只扣 `0.05`，比当前的 `0.10` 更温和。

对应奖励变成：

```text
不搜索答对：1.000
搜索一次答对：0.975
搜索两次答对：0.950
搜索三次答对：0.925
搜索四次答对：0.900
```

## 我的判断

当前 `B=2` 实验不是无效，它可以回答：

> 在 NQ 单跳、小预算条件下，成本奖励能否减少不必要的搜索？

但它不适合宣称：

> 完整复现论文的多轮、多跳搜索能力。

如果优先考虑简历和面试的完整叙事，我更赞成改为论文原版 `B=4`。不过不能只改 C 分支，R、B、C 和四路评测必须统一使用相同的 `max_turns=4`；否则 B/C 对比会混入搜索预算差异。进一步追求多跳意义时，还应把固定 512 条训练数据改成小规模 `NQ + HotpotQA` 混合，而不是只提高 turn 数。单纯在 NQ 上从 2 提到 4，更论文一致，但科学增量有限。
