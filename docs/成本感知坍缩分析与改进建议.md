# 成本感知坍缩分析与修复续跑方案

本文是 Search-R1-small 成本感知实验的后续执行依据。它保留已完成的 C / Cost-aware 失败实验，合并坍缩根因、正确性门控奖励、完整轨迹日志和最小续跑方案。若本文与旧规划中的 C 分支奖励或后续实验安排冲突，新的 `C-gated` 分支以本文为准；A、R、B、C-old 的历史结果和证据保持不变。

## 1. 当前结论与必须保留的失败证据

本轮 NQ-small 使用 train-512 / val-64 / test-128，正式 test-128 结果如下：

| 阶段 | 答对数 | EM | 总搜索 | 平均搜索 | 不搜索题数 | Utility |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A / Base | 5/128 | 0.0391 | 164 | 1.2813 | 29 | 0.0070 |
| R / Reproduced | 21/128 | 0.1641 | 167 | 1.3047 | 0 | 0.1314 |
| B / Control | 23/128 | 0.1797 | 131 | 1.0234 | 0 | 0.1541 |
| C-old / Cost-aware | 9/128 | 0.0703 | 4 | 0.0313 | 126 | 0.0695 |

C-old 将搜索调用相对 B 降低 96.95%，但少答对 14 题，统一 Utility 下降 54.88%，属于 no-search collapse，而不是成功的成本优化。训练前 5 步仍有 205 次搜索和 23/200 条正确轨迹；最后 5 步只剩 4 次搜索和 6/200 条正确轨迹，第 16、20 步均为 40/40 不搜索且 0/40 正确。

以下内容必须永久保留：

- C-old 的 checkpoint、训练日志、WandB offline、resolved config、曲线、终态、lineage 和 digest；不得覆盖、删除、改名为成功实验或自动重试到“成功”。
- `docs/results/search-r1-small-20260720/` 继续作为原始 A/R/B/C-old 权威结果。
- 后续模型使用新名称 `C-gated / cost_aware_gated`，不得复用 C-old 的结果目录。
- 面试表述应把 C-old 作为一次受控负结果：先观察坍缩，再从 GRPO 信用分配角度定位并修复，而不是隐藏失败实验。

## 2. 坍缩根因

C-old 的训练奖励为：

```text
r_old = EM - lambda * n_search / T_max
lambda = 0.10, T_max = 4
```

答错轨迹的奖励随搜索次数从 `0` 下降到 `-0.10`。每题生成 5 条轨迹后，GRPO 在同题组内计算：

```text
advantage_i = (reward_i - group_mean) / (group_std + 1e-6)
```

若 5 条轨迹全部答错，EM 不再提供区分，成本成为唯一排序信号。例如搜索次数为 `[0, 1, 1, 2, 4]` 时，不搜索的错误轨迹会获得正 advantage，高搜索错误轨迹获得负 advantage，模型因而被直接推动去学习“答错也不要搜索”。在全错组中把 `lambda` 从 `0.10` 改成 `0.001` 也不能根治，因为 mean-std 标准化基本消掉了统一缩放。

`(1-0.115)^5≈54%` 只能作为同题轨迹独立同分布时的直觉估算，不能当作实际观测。无需该假设也能得到严格下界：C-old 全程 160 个 group、64 条正确轨迹，因此至少 96/160 个 group 全错；最后 5 步 40 个 group、6 条正确轨迹，因此至少 34/40 个 group 全错。现有聚合日志不能还原精确全错组数，这也是本次必须补日志的原因。

准确结论不是“搜索永远不划算”。正确且搜索 4 次仍有 0.90，远高于错误不搜索的 0；问题发生在大量全错组中，错误不搜索被赋予了正向的相对优势。

## 3. 最终采用的奖励与评价定义

### 3.1 训练奖励：只在答对时计入成本

`C-gated` 使用：

```text
r_train = EM * (1 - lambda * n_search / T_max)
lambda = 0.10, T_max = 4
```

| 结果 | 0 搜索 | 1 搜索 | 2 搜索 | 3 搜索 | 4 搜索 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 答错 | 0 | 0 | 0 | 0 | 0 |
| 答对 | 1.000 | 0.975 | 0.950 | 0.925 | 0.900 |

该定义保证：

- 全错组内 reward 和 advantage 全为 0，彻底移除“错误但不搜索”的反向梯度。
- 任意正确轨迹始终优于任意错误轨迹；只有出现多个正确候选时才优先更低成本的轨迹。
- `lambda=0` 时严格等于原始 EM，现有 B 仍是有效控制组，无需重新训练。
- 改动只位于奖励与可观测指标，不修改 GRPO 核心算法。

一个必须如实说明的边界是：若同组只有一条正确轨迹，奖励形如 `[a,0,0,0,0]`，std 标准化会基本消掉 `a` 的尺度，此时成本不改变组内 advantage。成本信号主要来自“同组至少两条正确轨迹且搜索次数不同”的情况。该信号较稀疏，但它只在存在可比的成功方案时优化成本，符合“先答对，再省调用”的保守目标。

### 3.2 评价 Utility：继续计算所有真实调用成本

训练 surrogate 不能替换经济评价指标。训练、验证和最终报告必须同时保留：

```text
r_train = EM * (1 - 0.10 * n_search / 4)
u_eval  = EM - 0.10 * n_search / 4
```

失败轨迹的搜索成本不进入策略梯度，但仍进入 `u_eval`，因此不会在报告中掩盖真实浪费。日志字段必须明确区分 `em`、`train_reward`、`posthoc_utility` 和 `executed_search_count`；`val/utility` 与最终 `results.csv` 必须使用固定的 `u_eval`，不能直接复用 RewardManager 的训练输出。

## 4. 本轮明确不采用的改动

| 候选改动 | 本轮决定 | 原因 |
| --- | --- | --- |
| 去掉 std、mean-only / Dr. GRPO | 推迟 | 属于独立算法改动；若只改 C 会混入第二变量，若 B/C 都改则需要重训控制组 |
| `std` 下限 | 推迟 | 只能缩小而不能消除原奖励的反搜索排序，阈值 `0.1` 也缺少依据 |
| 第一次搜索免费 | 不采用 | B 已接近每题一次搜索；门控后再免费会让正确轨迹的 0/1 次搜索打平，几乎移除主要优化空间 |
| lambda 退火 | 不采用 | 原奖励下只能延迟问题；正确性门控后没有结构性必要 |
| group 5 改为 8/16 | 不采用 | 增加 rollout 成本和显存压力，仍不能治本，并破坏与已有 B/C 的单变量对照 |
| 延长 R 后重新分叉 | 不采用 | 增加成本并更换共同起点；当前没有证据说明继续训练 R 必然提高正确轨迹密度 |
| 多 lambda × 多 seed sweep | 首轮不做 | 先固定 `lambda=0.10` 验证结构修复；若结果有希望，优先补第二个 seed，而不是在 test 上调参 |

## 5. C-gated 单变量续跑设计

实验 lineage 为：

```text
                         -> B20（已有，EM reward）
R60 exact checkpoint ---+-> C-old20（已有，原始线性成本，失败证据）
                         -> C-gated20（新增，正确性门控成本）
```

C-gated 必须从现有 R60 的同一 checkpoint 和 digest 启动，不从 B、C-old 或 gate checkpoint 继续。除奖励公式和新增日志外，保持以下配置不变：

| 项目 | 固定值 |
| --- | --- |
| 模型 | Qwen3.5-2B，全参数 FSDP，bf16 |
| 硬件 | 2 张 RTX 5090 级 GPU |
| 数据 | train-512 / val-64 / test-128，seed 42 |
| 训练 | 20 steps，batch 8，group 5，每 step 40 条轨迹 |
| 搜索 | CPU BM25 top-3，最多 4 次真实检索 |
| 长度 | start 1024，observation 384，response 256，prompt 3584 |
| 优化 | LR `1e-6`，warmup ratio `0.285`，KL loss `0.001`，entropy `0.001` |
| 采样 | 训练 temperature `1.0`、top-p `1.0`；正式验证沿用现有固定 `do_sample=False` 路径 |
| 选择 | 固定 C-gated step 20；训练指标只告警，不按 EM/Utility 科研早停或事后挑 checkpoint |

现有 R、B、C-old 不重训。C-gated 新增训练与正式评测；B、C-old 只用已有 checkpoint 做一次 trace-only inference 回填，不更新权重。三路使用同一份 test-128、同一评测代码、同一生成配置和同一数据顺序。新的逐题输出属于 follow-up re-evaluation；即使仪器化后的数值与 2026-07-20 历史聚合结果略有差异，也单独报告而不覆盖旧表。

## 6. 全面日志与轨迹证据

本轮日志目标不只是画 loss 曲线，还要回答：哪道题答对或答错、模型显式生成了什么 `<think>`、何时搜索、搜了什么、看到了哪些信息、最终答案是什么，以及该轨迹为什么获得当前 advantage。

这里的“思考过程”仅指模型实际输出并保存在轨迹中的 `<think>...</think>` 文本，不声称能读取模型未输出的内部隐状态或潜在推理。

### 6.1 运行级 manifest

每个 attempt 固定记录：

- `run_id`、stage、父 checkpoint 路径与 digest、checkout commit/tree digest、resolved config digest；
- 模型、tokenizer、train/val/test、语料、BM25 index 与 CPU handoff digest；
- seed、奖励模式、lambda、`T_max`、group/batch/steps、GPU 数量；
- 开始/结束时间、原始 exit code、wall time、GPU-hours、估算人民币；
- trace schema version、各 JSONL 行数、文件 SHA-256 和最终归档 SHA-256。

### 6.2 训练轨迹 `train_trajectories.jsonl`

C-gated20 应有 `20 × 8 × 5 = 800` 条记录。每条至少包含：

```text
step, sample_id/source_index, group_uid, group_slot
question, gold_answers
raw_trajectory
turns[{turn, think, action, search_query, retrieved_docs, observation, valid_action}]
extracted_answer, em, executed_search_count
reward_em_only, train_reward, posthoc_utility
group_correct_count, group_reward_mean, group_reward_std, sequence_advantage
response_tokens, response_clipped, turns_used, invalid_action_count
```

`raw_trajectory` 保存模型实际看到的完整交互顺序，包括 `<think>`、`<search>`、格式化后的 `<information>` 和 `<answer>`。结构化 `turns` 同时保存每轮查询，以及 top-3 文档的 rank、可用 doc id、title、BM25 score 和模型实际看到的 observation；必须区分检索器原始结果与被 `max_obs_length` 截断后送入模型的文本。

轨迹和 `executed_search_count` 必须按样本一起重排，不能放在不会随 batch reorder 对齐的全局 `meta_info` 中。每 step 写完后 flush；attempt 成功前关闭文件、校验 800 条唯一记录并生成哈希。日志失败属于证据失败，不允许静默继续并把训练标成成功。

同时保留现有 per-step loss/训练曲线，并新增：

- `all_wrong_group_ratio`、每组正确轨迹数 `0..5` 的直方图；
- 正确/错误轨迹各自的平均搜索数和 no-search ratio；
- group reward std、sequence advantage 的均值/极值；
- EM、train reward、post-hoc Utility、响应长度、截断率、有效/无效 action 数。

不使用含义模糊的“成本 advantage 贡献比例”；必要时可由同组保存字段离线计算 EM-only 与 gated reward 的反事实差异。

### 6.3 正式评测轨迹 `eval_predictions.jsonl`

B、C-old、C-gated 各保存 128 条逐题记录，字段至少包括：

```text
stage, checkpoint_digest, sample_id/source_index
question, gold_answers
raw_trajectory, structured turns, extracted_answer
em, executed_search_count, posthoc_utility
response_tokens, response_clipped, turns_used, invalid_action_count
```

完整原始轨迹与检索文档可能较大，保存在持久数据盘和 evidence tar 中，不直接全部提交 Git；Git 结果目录只提交汇总 CSV、曲线、配对分析和少量经过检查的代表性轨迹。任何日志都不得包含 SSH 密码、API key、访问令牌或环境 secret。

### 6.4 配对分析产物

以稳定 `sample_id` 对齐 B、C-old、C-gated，生成：

- `paired_results.csv`：每题三模型的 EM、搜索数、答案和 Utility；
- `correct_questions.csv` / `wrong_questions.csv`：明确列出各模型答对、答错的题；
- `search_transition.csv`：`B_searches -> C_searches` 转移计数；
- 正确题和错误题分别按搜索次数 `0..4` 统计，并报告 `E[searches|correct]` 与 `E[searches|wrong]`；
- 四类对照：共同答对、B 对而 C 错、B 错而 C 对、共同答错；
- 每一类的题数、搜索差、Utility 差和 2-5 条代表性完整轨迹；
- B/C-old/C-gated 的训练曲线、最终柱状图和可重新计算全部表格的分析脚本。

只有“共同答对题中搜索调用下降”才能称为无损效率提升；B 对而 C 错必须明确标为有害节省；共同答错时少搜索只能称为减少无效调用，不能单独包装成模型能力提升。NQ 没有“理论需要几次搜索”的标签，B 的实际搜索数只能作为行为基线，不能写成 oracle 搜索次数。

## 7. 实现范围与测试要求

后续代码只做以下必要改动：

1. RewardManager 增加正确性门控奖励，并保持 `lambda=0` 与原始 EM 完全一致。
2. 分离 `train_reward` 与固定 `posthoc_utility`，修正训练、val、最终结果字段语义。
3. 增加按样本对齐的训练/评测轨迹记录器和 schema 校验。
4. 增加 B/C-old/C-gated 的逐题配对分析与结果打包。
5. 为云端脚本增加 `cost_aware_gated` stage，但不重构已验证的 launcher、锁、handoff 和关机状态机。

至少验证：

- 错误轨迹搜索 0..4 次时 `train_reward` 均为 0；正确轨迹奖励为 `1.0..0.9`；
- `lambda=0` 与旧 EM reward 逐元素一致；全错 group 的 advantage 为 0；
- `posthoc_utility` 始终使用 `EM - 0.10*n/4`，不受训练 reward mode 影响；
- batch repeat/reorder 后 sample、trace、EM、search count 和 advantage 仍严格对齐；
- raw transcript 可解析 think/search/information/answer，多轮、无搜索、无效 action 和截断都能正确记录；
- 800 条训练记录、每模型 128 条评测记录的唯一性、行数、schema 和哈希校验失败时 stage 非零退出；
- 现有奖励、搜索计数、NQ-small、结果导出和 shell 测试全部通过，生产配置可完整 compose。

## 8. CPU/GPU 执行顺序

### 阶段一：本地实现与提交

按第 7 节实现、运行聚焦测试和完整相关测试，生成新 commit 并 push。旧结果目录不修改；新结果使用独立目录。

### 阶段二：AutoDL 无 GPU 更新

实例不挂 GPU 时更新到固定新 commit，重做代码身份 seal、测试、配置解析和 CPU handoff。模型、数据、语料和 BM25 index 的 digest 未变时直接复用，不重新下载或重建，不完整重跑旧 CPU 准备。

### 阶段三：两卡 GPU

1. 验证新 handoff、R60/B/C-old checkpoint digest 和检索服务。
2. 从 R60 做 2-step `C-gated` GPU/日志 gate，验证 reward、trace、双卡训练、跨 step 记录和哈希；删除 gate checkpoint，只保留证据。
3. 不使用 gate 权重，从同一 R60 全新运行固定 `C-gated20`。
4. 正式评测 C-gated，并对 B、C-old 做 trace-only inference 回填；三路合计生成 384 条评测记录和配对分析，不重训 B/C-old。
5. 校验 checkpoint、trace 行数、结果重算、全部 digest，打包 evidence 后再发布终态。
6. 终态、原始 exit code、日志 sentinel 和 durable sync 完成后才允许 watchdog 请求关机；科学负结果也保留证据后正常关机，不自动重试。最终仍由用户在 AutoDL 控制台确认实例已停止且停止计费。

训练固定执行到 step 20。每步保存的 train EM、搜索数、no-search ratio、group 正确数和 Utility 用于观察趋势与事后诊断；只有 OOM、非有限值、检索服务失败、trace 对齐/行数/哈希失败等工程不变量才立即失败。中途训练指标变差不触发自动科学早停，因为用训练 batch 不能可靠替代固定 test-128 终点评价，提前停止还会改变预注册实验预算。

按既有实测，新增一支正常的 20-step 分支约 12 元；计入 2-step gate、三次评测、分析和运行开销后，预计约 20-30 元。本轮 GPU 硬上限设为 50 元，未经用户确认不得超出。新增原始轨迹远小于 checkpoint，不需要因日志再次扩容 100 GB 数据盘。

## 9. 预注册判据与结果解释

B 的固定参考 Utility 为 `0.1541`。设 test-128 的答对数为 `K`、总搜索数为 `S`，则：

```text
u_eval = (K - 0.025 * S) / 128
超过历史 B 的条件：K - 0.025 * S > 19.725
```

由于 B 已经只用 131 次搜索，至少 125 题恰好搜索一次，压缩重复搜索的空间很小。要超过 B：

| C-gated 平均搜索 | 至少答对 |
| ---: | ---: |
| 1.0 / 0.9 / 0.8 | 23/128 |
| 0.7 / 0.5 | 22/128 |
| 0.0 | 20/128 |

因此不预言平均搜索一定降到 `0.7-0.9`，也不接受“EM 损失个位数百分点”这种过宽标准。少答对 1 题损失 `1/128≈0.0078`，需要全测试集节省约 40 次搜索才能由当前成本权重抵消。

结果按以下四类解释：

- **强成功 / 无损成本优化**：C-gated 至少答对 23/128、总搜索少于 131，并在共同答对题中显示搜索下降。
- **成本效用权衡成功**：固定 `u_eval` 高于重新评测的 B，但答对数少于 23；只能表述为成本效用权衡，不能称为无损优化。
- **结构修复成功但无收益**：不再坍缩、EM 接近 B，但搜索和 Utility 没有显著改善；说明安全奖励有效，当前数据/正确轨迹密度不足以学到额外成本优化。
- **新的有效负结果**：Utility 未超过 B 或再次出现明显质量退化；完整保留，不追加单边步数、不挑 checkpoint、不事后 sweep 美化结果。

本实验仍是单 seed、test-128 的小规模方法复现，不能声称统计显著或达到论文大规模数值。若首轮结果有希望，下一优先级是增加第二个 seed；mean-only、std floor、免费首搜、更大 group、延长 R 和 lambda sweep 均留作独立后续消融。

## 10. 面试叙事

最终项目应能用一条完整证据链说明：
